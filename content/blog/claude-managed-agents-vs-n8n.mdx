Yesterday Anthropic quietly flipped the switch on something a lot of people have been waiting for: **Claude Managed Agents**, a hosted agent platform you can drive from the Claude Console, a new `ant` CLI, or straight from Claude Code.

The pitch is seductive. Instead of writing your own agent loop, wiring up a sandbox, babysitting long-running tasks, and re-writing prompts every time a model changes, you hand Anthropic a config and get back an autonomous agent running in their infrastructure. Session tracing, checkpointing, scoped permissions, container networking — all of it handled.

Which of course means people have started asking the question out loud: **"Can I finally cancel my n8n subscription?"**

I've spent the last day reading every doc page, the launch blog post, and the new API reference so you don't have to. Here's what Managed Agents actually is, how you get started, whether your Claude Code Pro or Max plan pays for it (spoiler: no), and whether this is a real n8n killer or something that quietly sits next to it on your bill.

## What Anthropic Actually Launched

On April 8, 2026, Anthropic [launched Claude Managed Agents](https://claude.com/blog/claude-managed-agents) as a public beta. The one-line description from the docs is brutally clear:

> "A pre-built, configurable agent harness that runs in managed infrastructure. Best for long-running tasks and asynchronous work."

Until now, if you wanted an autonomous Claude that could read files, run shell commands, browse the web, and execute code for hours at a time, you had two choices:

1. **Use Claude Code** on your own machine, and accept that the agent dies when your laptop sleeps.
2. **Build your own harness** with the Messages API — agent loop, tool execution, sandboxing, checkpointing, permissions, everything.

Managed Agents is the third option Anthropic thinks most people actually wanted. You define *what* the agent should do. Anthropic runs *where*.

<Callout type="info">
**Important branding note from the docs:** Anthropic explicitly asks partners not to call this "Claude Code" or "Claude Code Agent." The approved term is "Claude Agent." That distinction matters — Managed Agents is a separate product, not a hosted version of the Claude Code CLI.
</Callout>

## The Four Concepts You Need to Understand

The whole system revolves around four primitives. If you've used Kubernetes, these will feel familiar — it's "declarative agent config" the same way a Deployment is declarative workload config.

| Concept | What it is |
|---|---|
| **Agent** | The model, system prompt, tools, MCP servers, and skills. Created once, referenced by ID. Versioned. |
| **Environment** | A container template — pre-installed packages, network access rules, mounted files. |
| **Session** | A running agent instance inside an environment, executing a specific task. |
| **Events** | Messages flowing between your app and the agent — user turns, tool results, status updates. |

The flow is always the same: create an **agent**, create an **environment**, launch a **session** that references both, then stream **events** in and out over server-sent events.

This is a bigger deal than it sounds. Every production agent I've built has reinvented this exact data model. Now it's a versioned, Anthropic-managed primitive.

## Why This Matters: The "Build It Yourself" Tax Is Gone

If you've never built an agent from scratch, you might not appreciate what Managed Agents removes. Let me list the things I've personally wasted weeks on in past projects:

- **Sandboxing** — spinning up a firecracker/docker/gvisor container per session so the agent can safely run `rm -rf` on its own filesystem without touching mine.
- **Tool execution layer** — translating Claude's tool calls into actual subprocess runs, capturing stdout/stderr, streaming it back as tool results.
- **State persistence** — saving conversation history, file diffs, and tool outputs so the agent can resume after a crash or a disconnect.
- **Permission scoping** — deciding what filesystem paths, network endpoints, and credentials the agent is allowed to touch.
- **Observability** — logging every tool call, decision, and failure so you can debug when the agent does something stupid.
- **Model upgrades** — rewriting half your prompt engineering when Anthropic ships a new Sonnet.

Managed Agents absorbs all six. The harness is tuned by Anthropic, upgrades automatically, and ships with session tracing built into the Console. Every tool call, every decision, every failure mode is inspectable in a UI you didn't have to build.

That last point is bigger than the sandbox. I've shipped agents where the *only* reason we knew something was broken was because a user screenshotted the terminal and posted it in Slack. Built-in tracing changes that instantly.

<Callout type="tip">
The performance claim in Anthropic's launch post: **up to 10 percentage points of improvement on structured file generation tasks** versus standard prompting. That's the harness itself — prompt caching, compaction, and optimization tuning — not a new model. Free performance just for moving your agent into their runtime.
</Callout>

## How to Actually Use It (Three Entry Points)

Managed Agents ships with three ways in. Pick your poison.

### 1. The New `ant` CLI

Anthropic dropped a brand new command-line tool called `ant` alongside the launch. If you're on macOS:

```bash
brew install anthropics/tap/ant
xattr -d com.apple.quarantine "$(brew --prefix)/bin/ant"
ant --version
```

On Linux there's a direct tarball from the GitHub releases page, or you can `go install github.com/anthropics/anthropic-cli/cmd/ant@latest` from source (Go 1.22+).

Creating your first agent from the CLI looks like this:

```bash
ant beta:agents create \
  --name "Coding Assistant" \
  --model '{id: claude-sonnet-4-6}' \
  --system "You are a helpful coding assistant. Write clean, well-documented code." \
  --tool '{type: agent_toolset_20260401}'
```

The `agent_toolset_20260401` bundle enables the full set of built-in tools — bash, file read/write/edit/glob/grep, web search, web fetch. One line, Claude now has a full software engineering toolkit.

### 2. The SDKs

Every major language is supported from day one: Python, TypeScript, Java, Go, C#, Ruby, PHP. Python is three lines to spin up an agent:

```python
from anthropic import Anthropic

client = Anthropic()

agent = client.beta.agents.create(
    name="Coding Assistant",
    model="claude-sonnet-4-6",
    system="You are a helpful coding assistant. Write clean, well-documented code.",
    tools=[{"type": "agent_toolset_20260401"}],
)

environment = client.beta.environments.create(
    name="quickstart-env",
    config={"type": "cloud", "networking": {"type": "unrestricted"}},
)

session = client.beta.sessions.create(
    agent=agent.id,
    environment_id=environment.id,
    title="Quickstart session",
)
```

Then you open a stream with `client.beta.sessions.events.stream(session.id)`, send a user event, and iterate over events as they come back. The agent emits a `session.status_idle` event when it decides it's done.

### 3. Claude Code Itself

This is the one I care about most. The latest Claude Code ships with a built-in `claude-api` Skill that knows how to drive the Managed Agents API. You can tell Claude Code inside your terminal to *deploy a managed agent from this repo*, and it'll generate the config, create the agent, spin up the environment, and hand you back the session URL.

So the answer to "do I need to learn a new CLI?" is "not really" — Claude Code becomes the operator for you.

<Callout type="warning">
All Managed Agents API requests require a beta header: `anthropic-beta: managed-agents-2026-04-01`. The SDKs add it automatically. If you're hand-rolling curl, forget it and everything 404s. Don't be me at 11pm last night.
</Callout>

## The Subscription Question Nobody Wants to Ask

Here's the one I spent the most time chasing down, because it's buried three clicks deep in the pricing page: **your Claude Code Pro or Max subscription does not cover Managed Agents.**

Let me spell this out because it trips people up constantly.

Claude has two billing worlds that are completely separate:

1. **Claude.ai subscriptions** — Pro ($20/mo), Max ($100 or $200/mo), Team ($25-150/user/mo). These cover claude.ai chat, the Claude desktop apps, Claude Code running against your account, and Claude Cowork.
2. **API billing** — pay-per-token via the Anthropic Console, with your own API key. Standard rates ($3/MTok input, $15/MTok output for Sonnet 4.6, etc.).

The Agent SDK and Managed Agents API both live in world #2. From the docs:

> "All tokens consumed by a Claude Managed Agents session are billed at the rates shown in Model pricing. [...] Session runtime replaces the Code Execution container-hour billing model."

Translation: Managed Agents bills on **two dimensions** — tokens consumed by Claude, and session runtime (container-hours). You pay Anthropic directly through your Console account. Your shiny Max subscription? Completely orthogonal.

This is the same reason the Claude Agent SDK has had [an open GitHub issue](https://github.com/anthropics/claude-agent-sdk-python/issues/559) asking for Max plan billing support — it's a known gap, not a bug.

**What this means practically:**

- You still need a funded Anthropic Console account to run Managed Agents.
- A $20/month Pro plan gives you zero free managed-agent runtime.
- You can absolutely use Claude Code on your Max plan to *orchestrate* Managed Agents, but the agents themselves bill to your API key.
- Rate limits are 60/min for create operations, 600/min for read operations — per organization.

If you were hoping Max would silently cover it: no. If you were hoping a single bill would work: also no, at least for now.

## The Big Question: Does This Kill n8n?

Now for the real reason we're here. You have n8n running somewhere — probably self-hosted, probably doing 5-30 things for you quietly in the background — and you're wondering if Managed Agents means you can shut it down.

**Short answer: no. They solve different problems.**

Long answer: let me show you what each one is actually good at.

### Where n8n Wins

n8n is a **visual workflow automation platform** with something like 1,239 pre-built integration nodes. Its sweet spot is stitching SaaS tools together with deterministic logic:

- New Stripe charge → create a row in Airtable → send a Slack message → update HubSpot.
- Every hour, poll Shopify orders → filter for high-value customers → fire a drip campaign in Mailchimp.
- Webhook from Typeform → parse fields → create a Linear issue with the correct labels.

This is **not** reasoning work. This is connector plumbing. n8n has a battle-tested visual editor, a huge node library, scheduled triggers, retry logic, and state persistence — all the stuff you need to build a "glue the business together" workflow that runs forever without human babysitting.

A self-hosted n8n instance handling 10,000 workflow executions per month costs roughly **$50-150/month** including modest LLM calls mixed in. That's hard to beat on economics alone.

### Where Managed Agents Wins

Managed Agents is a **reasoning agent runtime**. Its sweet spot is tasks where the next step depends on the last step in ways you can't predict in advance:

- "Read this 200-page RFP, identify the requirements we can't meet, draft a gap analysis, and open a Linear ticket for each."
- "Triage this customer support ticket — actually read the logs, check the service status, hit the internal docs, and write a response."
- "Migrate this Python codebase from Flask to FastAPI. Run the tests. Fix what breaks."

These are tasks where a visual workflow doesn't help you, because the "workflow" is whatever Claude decides it needs to do in the moment. The value is in the reasoning, not the wiring.

### The Real Answer: Use Both

The most sophisticated teams I've seen in the last three months aren't picking one — they're using **Claude as the architect and n8n as the runtime**. There's an open-source `n8n-mcp` server that exposes n8n's 1,239 nodes and 2,646 pre-built configurations to Claude via MCP. You can literally tell Claude Code *"build me a lead qualification workflow that pulls from HubSpot, enriches with Clearbit, and writes to Airtable"* and it will design, validate, and deploy a working n8n workflow for you.

This pattern turns n8n into a **compilation target**. Claude handles the reasoning about what the workflow should do. n8n handles the boring, reliable execution of the workflow itself — cheaply, on your own hardware, without per-run LLM costs.

<Callout type="tip">
My current stack: **Claude Code** on my laptop for interactive work, **Managed Agents** for long-running autonomous tasks I don't want to watch, and **n8n** (self-hosted) for the boring connector plumbing that runs 24/7. They're additive, not substitutes.
</Callout>

## What's In Research Preview (And Why It Matters)

The launch included a list of features that aren't in the public beta yet but are in "research preview" — which in Anthropic-speak means *request access and you can try it*. Three of them are worth watching closely.

**1. Multi-agent coordination.** Agents can spawn and direct other agents to parallelize work. This is the difference between "Claude writes your code" and "Claude runs a team of Claudes that writes your code, reviews it, tests it, and ships it." The infrastructure for this has existed in the Claude Code ecosystem via subagent dispatch, but putting it in the Managed Agents runtime means you can run parallel agent fleets without managing orchestration yourself.

**2. Self-evaluation (outcomes).** You define success criteria. The agent iterates until it meets them — or it fails and tells you why. Today most agents need a human to check their work. Outcomes flips that: the agent checks its own work against a spec you defined, and only returns when it's satisfied.

**3. Memory.** Persistent memory across sessions. Your agent can remember things it learned in session #1 when you start session #47 two weeks later. Without this, every Managed Agent is effectively amnesiac between runs.

All three are the difference between "agents that are useful for an hour" and "agents that actually hold down a job." They're not shipping yet, but they're the signal that Anthropic knows exactly where this is going.

## The Gotchas I Hit in 24 Hours

A few things I ran into trying to ship my first real agent last night.

**The beta header is mandatory.** I already mentioned this. Every endpoint returns 404 without `anthropic-beta: managed-agents-2026-04-01`. The SDKs set it for you; raw HTTP does not.

**Unrestricted networking is the easy default.** The quickstart uses `"networking": {"type": "unrestricted"}`. That's fine for experiments. Before you point this at real workloads, lock it down — Managed Agents supports network policies, and you almost certainly don't want your agent able to reach arbitrary internal services.

**Container runtime isn't free.** Session runtime is billed on top of tokens. A long-running session with a lot of idle thinking time accumulates container-hours. If you're used to the old Code Execution tool's container-hour model, it's gone — runtime is folded into session billing now.

**Branding restrictions are real.** If you're shipping a product built on Managed Agents, read the branding section carefully. "Claude Agent" and "Powered by Claude" are approved. "Claude Code Agent" and anything that visually mimics the Claude Code CLI are not.

## Should You Use It?

Here's my decision framework after a day of poking at this:

- **You're building agents right now with the Messages API and your own sandbox.** Migrate. The harness alone is worth it, and you'll stop maintaining infrastructure that isn't your core product.
- **You're running Claude Code on your laptop for personal productivity.** Don't bother. Managed Agents doesn't replace your interactive loop — it's for tasks you delegate, not tasks you're watching.
- **You have n8n workflows that are mostly deterministic connector plumbing.** Keep n8n. Don't rebuild them as agents. Add Claude-as-architect on top if you want faster workflow authoring.
- **You have n8n workflows that keep breaking because the "logic" keeps changing.** Those are agent candidates. Move them to Managed Agents with a well-defined success criterion.
- **You have internal long-running jobs — batch processing, code migrations, data cleanup — that currently need a human to babysit.** Managed Agents is exactly for this. Start here.

<Callout type="info">
**My actual recommendation:** Don't cancel n8n. Sign up for the Managed Agents beta (your existing Console API key already has access — it's enabled by default). Pick one long-running task you've been procrastinating on, build it as a managed agent, and see what the session tracing tells you. That's the real test.
</Callout>

## The Bottom Line

Claude Managed Agents is the first time Anthropic has shipped a production agent runtime that's not disguised as a developer tool. Claude Code is an IDE. Claude Cowork is a desktop assistant. Managed Agents is infrastructure — the thing you build production agents *on*, the same way you build web apps on Vercel or Kubernetes.

It doesn't kill n8n. It doesn't replace Claude Code. What it does is eliminate the "build your own agent loop and babysit it forever" tax that every serious production agent has been paying for the last two years. That's a significant shift.

If you're still writing your own agent harness in 2026, the question isn't whether to migrate — it's when. Probably this week.
