1. Resend Audience sync NEW

Design principle

Your DB stays the source of truth. The Resend audience is a mirror, never read from. If the mirror falls out of sync, re-run the backfill. This keeps you safe from vendor lock-in and avoids dual-write race conditions driving correctness.

Why not more

Interstitial/full-screen modals, blocking overlays, and “no thanks, I don’t want to grow” dark-patterns actively damage trust on a personal brand site. These surfaces add more chances to sign up without blocking the page; their effect on conversion hasn’t been measured.

Risks & how we handle them

RiskMitigation
Resend API hiccup blocks a signupAudience sync is fire-and-forget with try/catch. Signup always succeeds if the DB write does. Failures logged, not surfaced to user.
Backfill double-adds contactsResend’s create-contact is idempotent by email within an audience. Re-runs are safe.
Drift between DB and ResendBackfill script can be re-run any time. DB is source of truth; Resend is a cache.
Aggressive signup feels spammy to loyal readersAll new surfaces respect a SUBSCRIBED_KEY flag so returning subscribers never see them. Sticky bar has its own dismiss flag. If feedback is bad, roll back by changing component mounts.
Stale NEWSLETTER_CUTOFF_DATE envNot touched by this plan. Runbook already documents it.
