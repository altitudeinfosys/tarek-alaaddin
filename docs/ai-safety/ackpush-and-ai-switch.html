Ways to turn the AI off

MethodSpeedNotes
Phone: tap Turn off AI on any fit-check or cap pushSecondsNeeds the webhook set up (step 3). The confirmation push has Turn AI back on.

# status (switch, today's usage, caps)
curl -H "Authorization: Bearer $CRON_SECRET" https://www.tarekalaaddin.com/api/admin/ai-switch

# turn off / on
curl -X POST -H "Authorization: Bearer $CRON_SECRET" -H "Content-Type: application/json" \
  -d '{"enabled":false}' https://www.tarekalaaddin.com/api/admin/ai-switch
If the database can't be read, the switch fails open: the AI stays on, so a Neon outage doesn't break the fit check. The env var is the hard stop for that case.

One-time setup

  1. Done 2026-11-14: both tables created on production Neon and checked with a live test of the switch and cap. For reference: create the two tables before merging. Run only the statements in drizzle/0001_ai_switch.sql (app_settings, ai_usage_daily) against production Neon, for example in the Neon SQL editor. Don't use drizzle-kit migrate: the first schema went in with drizzle-kit push, so there's no migrations table and migrate would try to rerun 0000. Nothing existing changes. Until the tables exist, the switch and cap log errors and stay open.
  2. In the AckPush console (ackpush.com), create an app for this site, for example "tarekalaaddin.com", and create an API token for it. Use a new token, not the Claude Code one.
  3. Set the app's webhook URL to https://www.tarekalaaddin.com/api/webhooks/ackpush (with www: the bare domain answers with a 308 redirect, which webhooks don't follow). The console shows a signing secret once; copy it.
  4. Add the Vercel env vars (Production), then redeploy:
    VariableValueRequired
    ACKPUSH_API_TOKENToken from step 2Yes, for pushes
    ACKPUSH_WEBHOOK_SECRETSecret from step 3Yes, for the phone button
    FIT_CHECK_DAILY_CAPDefault 30; 0 pauses the fit checkNo
    CHAT_DAILY_CAPDefault 300 messages; 0 pauses the chatNo
    AI_FEATURES_DISABLEDtrue only for a hard stopNo
  5. Test: run one fit check on the live site, confirm the push arrives, tap Turn off AI, check the fit check now says "temporarily unavailable", then tap Turn AI back on.
With no ACKPUSH_API_TOKEN set, pushes are skipped silently, and signups and fit checks work exactly as before.

Other abuse limits in this change

  • Fit check now needs a Cloudflare Turnstile pass, using the same keys as /subscribe.
  • A request whose Claude call fails without being billed (connection error, timeout, or an error status such as 500 or 529 overloaded) gives its slot back, so an Anthropic outage doesn't use up the day's cap. A billed failure, such as a refusal or a reply that's cut off or can't be read, keeps its slot, so the cap stays a hard limit on spend.
  • Webhook answers older than the switch's last change are ignored, so a late retry can't undo a newer change.
  • Ask AI chat accepts at most 40 turns: visitor turns up to 4,000 characters, earlier assistant replies up to 12,000. The widget sends the last 19 turns.
  • Name and email on the fit check are optional. They aren't saved on the site or added to the newsletter. They do stay in your AckPush message history.
